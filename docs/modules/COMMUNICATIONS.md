# Communications

Driver Home keeps a Signal Ink quick-broadcast panel above bottom navigation in idle and active-trip states. The presets are whatever `GET /api/conversations/presets` returns, never a local list; today that is two, "On my way" and "Delay · 10 min". A driver mid-route taps rather than browses, so the grid stays short. Each preset opens a review sheet containing exact server wording, Colombo date, audience, and recipient count; Send is the second action. Audience selection exposes selected riders.

The driver app no longer composes message wording itself. Every broadcast it sends is a server preset chosen from the grid, so the review sheet shows the same sentence the server will deliver. Custom announcements, open-ended delays, future service-unavailability notices, and linked corrections were removed along with the More updates screen (2026-09-10).

Failed/offline drafts persist in AsyncStorage and are sent only after an explicit retry. Stable request IDs prevent duplicate messages after lost responses. Broadcast progress persists near the panel, and retry submits failed recipients only. The cancellation strip remains until its exact absence revision is explicitly acknowledged.

Private rider-driver messaging was removed on 2026-09-10, and the Messages tab with it. Riders had had no way to send anything since user-app dropped its own conversation screens, so the driver's inbox could only ever receive broadcast copies and system absence notices — both of which the server still writes, and neither of which needed a screen. `Conversation`, `RiderAudience` and the pushed `Absences` routes are gone; the deep link that opened a conversation from a push is gone with them, so the in-app banner is now informational and dismiss-only.

The freed tab is **Riders**, a segmented screen: *Riders* lists who the driver currently carries, *Absences* lists who is away today. Only the visible segment is mounted, so the hidden one is not fetched. The Home panel's cancellation strip and absence chip deep-link into the Absences segment.

The riders list is a row per rider — name, then grade, organization and pickup label — and opens a rider's profile: name, grade, rider code and one contact number. **No rider picture appears anywhere in the driver app** (2026-09-11): a driver scans for a name and a pickup, not a face, so `RiderAvatar` and the `riderAvatarCache` were removed. The roster's `hasAvatar`/`avatarVersion` and `GET /api/driver/riders/:riderId/avatar` still exist on the backend and are simply unused here. **No home address appears anywhere**; a driver sees the pickup label only, and the server never sends more. Grade is shown only for a SCHOOL rider, since that is the only category signup asks (`gradeLine` in `state.js` prefixes a bare number, so "7", "Grade 7" and "Year 10" all read naturally).

The Absences segment (2026-09-11) is a read-only `Today · DD/MM/YYYY` caption (riders can only report the current day, so the driver never picks a date), a search box, and one plain row per rider whose status is `ABSENT` today — the same `RiderRow` as the riders list, with organization · pickup label beneath the name, tapping through to the rider's profile. Cancelled and retired notices are not listed; a cancellation is acknowledged from the Home strip. Neither segment has a summary count, an Updated/Refresh row or a timer: communications lists load when opened and reload only when `CommunicationProvider` invalidates them — on a `communication:event` from the socket (the backend emits one to `driver:<id>` for every absence transition), on socket reconnect, on app foreground, and on a push notification. QR boarding remains independent and surfaces a planned-absence discrepancy after a valid scan.

Communication screens distinguish loading, offline-without-cache, load failures, search misses, and true empty results. The root Riders tab has no misleading Back action, while the pushed rider profile retains one. A rider whose enrollment has ended answers 404 and reads as "no longer enrolled with you" — the server deliberately does not distinguish that from a rider id that never existed. All pages protect the bottom safe area, long rider/driver names wrap, confirmation sheets scroll internally, and actions keep a 56-point minimum target. The Home quick-broadcast panel is bounded to roughly 55–58% of the viewport and scrolls independently so every preset and review action remains reachable on a 360×800 screen and with enlarged text.

The authenticated `CommunicationProvider` owns Socket.IO and push registration for the full signed-in session. Configure `EXPO_PUBLIC_EAS_PROJECT_ID`, EAS push credentials, and `GOOGLE_SERVICES_FILE` for Android development/production builds. Expo Go cannot validate remote push delivery; use a configured development build and a physical device.
